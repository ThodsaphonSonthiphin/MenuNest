Undo, Redo และ Change history ทำงานยังไง (#106)

กด ถัดไป → เพื่อดูทีละ step

Step 0 / 0 เริ่มต้น
🤔 คำถาม — ตอบในใจก่อนกด ถัดไป
ทศพลกด Undo. แอปต้องส่งอะไรไปที่ server?
  • ก. "ตั้งค่ากินเป็น ฿0" — เพราะก่อนหน้านี้มันเป็น ฿0
  • ข. "ลบ ฿300 ออกจากค่ากิน" — เพราะทศพลใส่เข้าไป ฿300
ตอนนี้ทั้งสองข้อให้ผลเท่ากัน คือ ฿0. เลือกข้อไหนก็ดูเหมือนถูก. กด ถัดไป เพื่อดูว่าทำไมมันไม่เท่ากัน
⚖️ สองวิธี ผลไม่เหมือนกัน

❌ Rollback — เอาค่าเก่ากลับไปใส่

ส่ง ค่ากิน = ฿0 เพราะก่อนหน้านี้เป็น ฿0
ผล: ค่ากิน ฿0 — เงิน ฿100 ของมาลีหายไป

✅ Compensating — ส่งคำสั่งตรงข้าม

ส่ง ค่ากิน −฿300 เพราะทศพลใส่ ฿300
ผล: ค่ากิน ฿100 — เงินของมาลีอยู่ครบ
🧾 ราคาที่ต้องจ่าย
  • ทุกคำสั่งต้องมีคำสั่งตรงข้าม. ถ้าเขียนคำสั่งใหม่แล้วลืมเขียนตัวตรงข้าม ปุ่ม Undo จะพังเงียบ ๆ
  • บางคำสั่งไม่มีตรงข้าม. เช่น ลบซองทิ้ง. ต้องตัดสินว่าจะไม่ให้ undo หรือจะเปลี่ยนวิธีลบ
  • รายการที่จดไว้อาจใช้ไม่ได้แล้ว. ซองถูกลบ เดือนเปลี่ยน หรือคนอื่นแก้ทับ
  • เก็บไว้ที่ไหน. ในหน่วยความจำ (หายเมื่อ refresh) หรือบน server (ตามไปทุกเครื่อง)
สามข้อนี้คือ ticket reversible-actions, stale-undo และ history-storage บนแผนที่ ยังไม่ได้ตัดสิน
